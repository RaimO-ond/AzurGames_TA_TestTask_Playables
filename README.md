Задание 3
1. Какие проблемы производительности могут быть при сборке такой сцены.
   - Избыточные текстуры и Draw Calls: Множество объектов собирались из раздельных слоев графики
   - Избыточный размер текстур для короткой и небольшой сцены
   - Избыточные трисы/полигоны, кости для анимации у 3д моделей
   - Избыточные просчеты освещения
   - Избыточные эффекты
   - Проблемы с камерой с учетом смешения 2д фона и 3д моделей
  
3. Какие решения применены.
   - Разные слои спрайтов склеены в единые спрайты
   - Уменьшены разрешения исходных спрайтов
   - Уменьшено количество костей для анимации у 3д модели орка
   - Отключены статический и динамический батчинг в соответствии с тестовым заданием
   - Отключено освещение, используются unlit шейдеры
   - Реализован статичный FOV камеры и скролл для горизонтальных экранов, чтобы камера не показывала лишнего. Также скролл ограничен сверху и снизу
   - Установлены корректные настройки импорта текстур, такие как отключение лишних параметров (generate physics shape, generate mipmaps, read/write) и тд
   - Использовано сжатие текстур, которое обычно применяется для WebGL
   - Все спрайты, кроме фона, упакованы в один спрайт атлас (фон занял бы слишком много места в атласе, что в итоге увеличило бы вес)
   - Все 20 орков используют 1 материал, что уменьшает SetPass calls
   - Использованы не все данные ассеты, тк часть из них минимально отличается друг от друга. Неиспользуемые удалены из проекта
   - Удалены неиспользуемые ресурсы TMP
   - Атлас для нового шрифта сгенерирован только с используемыми символами
   - Настройки проекта, усиливающие оптимизацию неиспользуемого кода, настройки билда включают максимальное сжатие (формат сжатия Brotli)
4. Какие метрики получены после оптимизации.
   - Batches = 28
   - SetPass calls = 9
   - Tris ~36k
   - Папка Build после сборки WebGL билда весит 3.91мб
5. Почему были выбраны именно эти технические подходы:
   - Специфика Playable Ads требует жесткой экономии веса для соответствия требованиям рекламных сетей и ресурсов конечного девайса,
     поэтому было отключено и удалено всё, что не используется в данной сцене (освещение, атласы текстов, лишние символы и тд), а также
     выставлены настройки, которые позволяют максимально сэкономить финальный вес
6. Значения До и После оптимизации с обоснованием, почему они достаточны для плеебла:
   - Значения ДО оптимизации
      - Batches = 57
      - SetPass calls = 34
      - Tris ~41k
      - Папка Build после сборки WebGL билда весит ~14 мб
   - Значения ПОСЛЕ оптимизации
      - Batches = 28
      - SetPass calls = 9
      - Tris ~36k
      - Папка Build после сборки WebGL билда весит 3.91мб

     Обоснование: текущий размер финального билда с запасом укладывается в лимит 5мб, которые считается стандартом для плееблов.
     Также, цифровые показатели производительности (Batches, Tris, SetPass calls) соответствуют рекомендованным для плееблов (в тч на ресурсах Юнити)
     и позволят корректно воспроизводить геймплей на большом количестве конечных девайсов
